# 작품 제외 & 아카이빙

---

## A. 작품 제외 기능

배우와 동일하게 작품도 수동 제외 처리 가능. 제외된 작품은 대회/티어/대시보드에서 자동 제외.

### A-1. 작품 제외 (배우 제외와 동일 패턴)
- `works` 테이블에 `is_excluded` 컬럼 추가
- 작품 상세(WorkForm)에서 수동으로 제외/해제 처리
- 제외된 작품은 대회/티어/대시보드에서 빠짐
- **제외 UI** (배우 쪽 참고):
  - WorkForm: 제외 체크박스 추가 (ActorForm 참고: `<input type="checkbox">` + `제외` 라벨)
  - WorkDetailModal: 제목 옆 `제외됨` 배지 (ActorDetailModal 참고: `bg-orange-900/60 text-orange-400`)
  - CardTooltip/WorkCard: 작품 툴팁에 `제외됨` 표시 (CardTooltip 참고: `text-red-500`)
  - ActorDetailModal 우측 출연작: 제외 작품 빼고 재생 가능한 작품만 표시
  - 배우 작품 전체보기 모달: `제외숨김/제외포함/제외한정` 3상태 토글 추가

### A-2. 배우탭/작품탭 제외 필터 3상태 토글

토글 버튼 1개가 클릭마다 3상태 순환. 버튼명 4글자 통일.

`제외숨김` → `제외포함` → `제외한정` → `제외숨김` ...

| 상태 | 버튼명 | 동작 |
|------|--------|------|
| 숨김 | `제외숨김` | 제외 작품/배우 안 보임 (기본) |
| 포함 | `제외포함` | 전체 다 보기 (제외 포함) |
| 한정 | `제외한정` | 제외된 것만 보기 |

배우탭, 작품탭 동일한 패턴.

### A-3. 파일상태 필터 (버튼 그룹 4택)

작품탭과 배우 전체작품 모달에 파일상태 필터 추가. 소형 버튼 그룹으로 4택 중 1개 활성.

`[전체] [파일] [링크] [없음]`

| 버튼 | 동작 |
|------|------|
| `전체` | 필터 없음 (기본) |
| `파일` | 로컬 파일이 있는 작품만 |
| `링크` | URL만 있고 로컬 파일 없는 작품 |
| `없음` | work_files 레코드가 하나도 없는 작품 |

적용 위치:
- Works.tsx 검색 조건
- 배우 작품 전체보기 모달

### A-4. 대회/티어/대시보드 제외
- **대회(cup)**: getEligibleItemIds() 작품 쿼리에 `w.is_excluded = 0` 조건 추가
- **티어(tier)**: 동일 조건 추가
- **대시보드**: 통계 쿼리에서 제외 작품 빠지도록 처리

### 구현 순서 (A)

**Phase 1 — 작품 제외 기능 + 3상태 필터 + 파일상태 필터 + 제외 UI**
1. `works` 테이블에 `is_excluded` 컬럼 추가 (db.ts 마이그레이션)
2. `works:update` IPC에 `is_excluded` 반영
3. WorkForm.tsx에 제외 체크박스 추가
4. WorkDetailModal에 `제외됨` 배지 표시
5. CardTooltip/WorkCard에 `제외됨` 표시
6. Works.tsx에 `제외숨김/제외포함/제외한정` 3상태 토글 + works:list 필터 반영
7. Works.tsx에 파일상태 버튼 그룹 `[전체][파일][링크][없음]` 추가 + works:list 필터 반영
8. Actors.tsx 기존 제외 필터를 `제외숨김/제외포함/제외한정` 3상태로 변경
9. ActorDetailModal 우측 출연작에서 제외 작품 제외 (재생 가능 작품만 표시)
10. 배우 작품 전체보기 모달에 `제외숨김/제외포함/제외한정` 3상태 토글 + 파일상태 버튼 그룹 추가

**Phase 2 — 대회/티어/대시보드 제외**
1. ipc-cup.ts — getEligibleItemIds() 작품 쿼리에 `w.is_excluded = 0` 조건 추가
2. ipc-tier.ts — 동일 조건 추가
3. ipc-dashboard.ts — 통계 쿼리에서 제외 작품 빠지도록 처리

## B. 폴더 삭제 아카이빙 & cover images

파일은 삭제하되 작품 정보(태그, 배우, 평점, 코멘트 등)는 DB에 유지하는 아카이빙 기능.

### B-1. 폴더 삭제 기능 수정 (아카이빙)

기존 폴더 삭제에 cover images 이동 로직 추가. 작품 폴더의 **상위 폴더** 아래에 `cover images/` 폴더를 만들고, 커버 이미지를 작품 폴더명으로 리네임하여 보존.

**폴더 구조 예시:**
```
기타작품/
  ├── 2026-10-10 AAA-001/        ← 삭제 대상
  │     ├── AAA-001.mp4
  │     └── AAA-001.jpg
  └── cover images/               ← 자동 생성
        └── 2026-10-10 AAA-001.jpg ← 작품 폴더명.jpg
```

**배우 폴더 케이스도 동일:**
```
미나미 코즈에 1994-11-30/
  ├── 2021-05-11 KIRE-038/        ← 삭제 대상
  │     ├── KIRE-038.mp4
  │     └── KIRE-038.jpg
  └── cover images/
        └── 2021-05-11 KIRE-038.jpg
```

**아카이빙 흐름:**
1. 작품 폴더의 상위 폴더 아래에 `cover images/` 생성 (없으면)
2. 커버 이미지를 `cover images/작품폴더명.jpg`로 이동+리네임
3. DB `cover_path` 새 경로로 업데이트
4. 원본 작품 폴더 삭제
5. `work_files`에서 `type = 'local'` 레코드만 삭제 (URL은 유지)
6. `works` 레코드 자체는 유지 (아카이빙)

### B-2. 폴더스캔 시 cover images 자동 등록 (아카이빙 역방향)

기존 폴더스캔에 통합. `cover images/` 폴더를 만나면 내부 이미지 파일을 파싱하여 처리.

**파일명 파싱:**
```
cover images/2026-10-10 BBB-001.jpg
             ^^^^^^^^^^  ^^^^^^^
             release_date product_number
```

**자동 추출 정보:**
- `release_date` — 파일명 앞 날짜
- `product_number` — 파일명 뒷부분
- `cover_path` — 해당 이미지 경로
- **배우 자동 배정** — 상위 폴더가 `배우명 YYYY-MM-DD` 패턴이면 해당 배우 자동 연결

**처리 흐름:**
1. 폴더스캔 중 `cover images/` 디렉토리 감지
2. 내부 이미지 파일 순회
3. `product_number`로 기존 등록 여부 확인
4. **미등록** → 작품 생성 (work_files 없이, cover_path만 설정), 상위 폴더가 배우 패턴이면 배우 배정
5. **등록됨 + cover_path 없거나 파일 사라짐** → cover images 이미지를 작품 폴더로 이동 + `AAA-001.jpg`로 리네임 + cover_path 업데이트 (자동)
6. **등록됨 + cover_path 있고 파일 존재** → 스캔 일시 정지, 비교 모달 표시:
   - 좌: 기존 커버 / 우: cover images 커버
   - `교체` — cover images 것으로 교체 (기존 삭제, 새 이미지를 작품 폴더로 이동)
   - `삭제` — cover images 것 삭제 (기존 유지)
   - `무시` — 둘 다 유지, 스킵

**성능:** 이미지 파일 수가 적고 DB INSERT가 가벼워서 기존 스캔에 체감 차이 없음

### 구현 순서 (B)

**Phase 3 — 폴더 삭제 아카이빙**
1. 아카이빙 IPC 핸들러 — 커버 이미지 `cover images/`로 이동 + cover_path 업데이트 + 폴더 삭제 + work_files local 레코드 삭제
2. WorkForm.tsx — 폴더 삭제 버튼에 아카이빙 로직 연결

**Phase 4 — 폴더스캔 cover images 통합**
1. 폴더스캔 로직 — `cover images/` 디렉토리 감지 + 이미지 파싱 + 미등록 작품 자동 등록
2. 커버 충돌 모달 — 이미 등록된 작품의 커버와 cover images 커버가 둘 다 있을 때 비교/선택 UI
