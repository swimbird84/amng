# 2026-06-23 미해결 이슈 정리

## 1. cup:tournament-stats 0회 참가자 미표시

### 원인
`participated` 계산 시 `cup_entries`에 남아있는 **삭제된 배우/작품**이 포함되어 `participated`가 `totalEligible`보다 크거나 같아짐 → `zeroCount <= 0` → 0회 막대 미표시

### 위치
`src/main/ipc-cup.ts` — `cup:tournament-stats` 핸들러 (1953~1965행)

### 수정 방향
`participated` 쿼리에 `actors`/`works` 테이블 JOIN 추가하여 현존 아이템만 카운트

```sql
-- 현재 (삭제된 배우 포함)
SELECT COUNT(DISTINCT e.item_id) AS cnt
FROM cup_entries e
JOIN cup_runs r ON r.id = e.run_id
JOIN cup_tournaments t ON t.id = r.tournament_id AND t.is_master = 1 AND t.type = ?

-- 수정 (현존 배우만)
SELECT COUNT(DISTINCT e.item_id) AS cnt
FROM cup_entries e
JOIN cup_runs r ON r.id = e.run_id
JOIN cup_tournaments t ON t.id = r.tournament_id AND t.is_master = 1 AND t.type = ?
JOIN actors a ON a.id = e.item_id  -- 추가
```

work 타입도 동일하게 `JOIN works w ON w.id = e.item_id` 추가

## 2. cup:tournament-stats 0회 계산 필터 불일치

### 원인
`cup:start`의 풀 구성에서 처리하는 필터와 `cup:tournament-stats`의 `totalEligible` 계산에서 처리하는 필터가 다름

### cup:start에서 처리하는 필터 (풀 구성)
- tagIds (include/exclude, and/or)
- actorIds (include/exclude)
- ratingFrom/To
- heightFrom/To, bustFrom/To, waistFrom/To, hipFrom/To, cupFrom/To
- scoreExcluded, favoriteOnly
- studioIds (works)
- **selectedDivisions** (마스터 대회)

### cup:tournament-stats에서 처리하는 필터 (0회 계산)
- tagIds (include만, exclude 미처리)
- favoriteOnly
- **나머지 전부 누락**

### 위치
`src/main/ipc-cup.ts` — `cup:tournament-stats` 핸들러 (1986~2012행)

### 수정 방향
`cup:item-count` 핸들러가 이미 `cup:start`와 동일한 필터를 적용하므로, 해당 로직을 재사용하거나 `totalEligible` 계산을 `cup:item-count`와 동일하게 맞추기

## 3. 삭제된 배우/작품의 cup_entries 잔존

### 원인
`actors:delete` / `works:delete` 시 `cup_entries`에서 해당 item_id를 삭제하지 않음. `cup_entries.item_id`에 CASCADE 제약이 없음.

### 영향 범위
- `cup:tournament-stats`의 `participated` 과다 집계 (이슈 1)
- `cup:division-counts`의 `master_run_count` 과다 집계 가능성
- `master-ranking:rank-trends`의 이전 순위 계산 시 삭제된 아이템 포함

### 위치
- `src/main/ipc-actors.ts` — `actors:delete` (437행)
- `src/main/ipc-works.ts` — `works:delete` (367행)

### 수정 방향
삭제 시 `cup_entries`에서도 해당 item_id 정리하거나, 조회 시 현존 아이템만 JOIN하여 필터링

## 4. 일반 대회 통계 — 필터 미적용 참가자가 0회에 포함

### 원인
일반 대회의 `cup:tournament-stats`에서 0회 참가자를 계산할 때, `totalEligible`이 대회 필터를 제대로 반영하지 않아 **필터에 해당하지 않는 배우/작품까지 0회로 집계**됨

### 예시
- 일반 대회에 태그 필터 "A태그 포함"이 걸려 있음 → 풀 구성 시 A태그 배우 50명만 대상
- 통계 0회 계산 시 `totalEligible` = 전체 배우 400명 (필터 미반영)
- `participated` = 해당 대회 참가자 30명
- `zeroCount` = 400 - 30 = 370 → **실제로는 50 - 30 = 20이어야 함**

### 위치
`src/main/ipc-cup.ts` — `cup:tournament-stats` 핸들러 (1986~2012행)
이슈 2와 동일 위치. 일반 대회의 경우에도 `cup:start`와 동일한 필터를 `totalEligible` 계산에 적용해야 함.

### 수정 방향
이슈 2의 수정과 함께 해결. `cup:item-count`의 필터 로직을 재사용.

## 5. 마스터 토너먼트에서 미분류 배우 1명 누락

### 현상
79명 풀, 16강 마스터 토너먼트 대회에서 미분류 배우 4명 중 3명만 참가되고 1명이 빠짐

### 추정 원인
`cup:start`의 토너먼트 풀 구성 로직에서 참가자 선발 시 미분류 배우가 누락되는 경우가 있을 수 있음. 확인 필요 사항:
- `divisionMap`에서 새 배우의 division이 0으로 올바르게 매핑되는지
- `selectedDivisions` 필터에 0(미분류)이 포함되어 있는지
- 79명 풀에서 16명 선발 시 셔플/정렬 과정에서 누락되는지
- `forcedItems` 로직(최소 참가 보장)에서 미분류 배우가 제외되는 조건이 있는지

### 위치
`src/main/ipc-cup.ts` — `cup:start` 핸들러, 토너먼트 참가자 선발 부분 (1330~1410행 부근)

### 수정 방향
디버깅 필요. 실제 대회 설정(filter_json, selectedDivisions)과 함께 풀 구성 과정을 추적해서 원인 특정

## 6. 마스터 랭킹 테이블 추이 배지가 변동 있는데도 = 표시

### 현상
마스터 랭킹 테이블의 추이 컬럼에서 순위 변동이 있는 배우인데도 `=`로 표시됨

### 추정 원인
`master-ranking:rank-trends`에서 이전 순위(prevRank)와 현재 순위 계산 시 `recentRunLimit` 변경 후 로직이 맞지 않을 수 있음. 또는 `buildPointsAtTimeSql`로 변경한 이후 이전 시점 포인트 계산이 달라졌을 가능성.

### 위치
`src/main/ipc-cup.ts` — `master-ranking:rank-trends` 핸들러

### 수정 방향
현재 순위와 이전 순위 계산 로직이 동일한 기준(recentRunLimit)을 사용하는지, 이전 시점 포인트 쿼리가 정확한지 디버깅 필요
